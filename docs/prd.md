# 루티드 관리 화면 PRD (기획서 요약본)

상태: 완료
출처: 「루티드 예식 응대 AX 기획서」(2026-10-23, @주ㄴ성)을 PRD로 간주해 요약했다. 기획서에서 미정인 항목은 `[가정]`으로 표시한다.

## 1. 한 줄 정의

웨딩 공간 루티드의 문의부터 후기까지 고객 한 쌍의 여정을 한 줄로 보고, 대금·인원·발주·요청사항 일정을 놓치지 않게 돕는 준성 전용 관리 화면.

## 2. 사용자

- **준성(운영자)**: 모든 화면 사용. 통화·답사·당일 운영을 직접 한다.
- **[가정] 당일 스태프**: 예식 당일 체크 화면만 연다. (기획서 '확정 필요 사항'에서 계정 생성 여부 미정)
- 고객은 이 화면을 보지 않는다. 고객에게 나가는 연락은 준성이 직접 보낸다.

## 3. 핵심 원칙

1. AI(Gemini)는 초안만 쓰고, 고객 연락은 준성이 확인한 뒤 직접 보낸다.
2. 고객 1명 = 시트 1행. 문의 → 연락 → 답사 → 견적 → 계약 → D-day 준비 → 예식 당일 → 정산·회고 → 후기 요청 → 콘텐츠화.
3. 관리 화면은 구글 시트·캘린더·드라이브를 읽어 보여주는 Apps Script 웹앱이다. (구현은 2차 작업, 오늘은 시안 확정)

## 4. 데이터 (화면이 읽는 것)

- **메인 시트**: 문의(접수 일시, 이름, 연락처, 행사 종류, 희망 날짜 1·2순위, 낮/저녁, 예상 인원, 유입 경로, 문의 내용) / 영업(진행 단계, 첫 연락일, 답사일, 견적 발송일, 분위기, 예산 감, 중요 기준, 결정권자, 하객 지역, 특이사항) / 계약(계약일, 예식일, 슬롯, 패키지, 옵션, 총액, 계약금·중도금·잔금과 입금 여부, 초상권 동의) / 자동 계산(D-90~D-1 날짜, 다음 할 일, 캘린더 생성 여부) / 사후(원본 수령, 후기 요청·작성, 콘텐츠 활용, 회고) / 실패(단계, 사유)
- **예식 상세 탭**: 최종 인원, 알레르기, 입장 동선, 축가, 음악 큐시트, 외부 업체 연락처, 신부대기실 시간
- **상담 기록 탭**: 고객 ID, 상담일, 방식(전화/답사/미팅/카톡), 내용 요약, 레퍼런스 사진(드라이브 링크·장수)
- **요청사항 탭**: 고객 ID, 파트(주방/무대/플라워/음향/서빙), 요청 내용 한 줄, 출처, 레퍼런스, 고객 최종 확인(D-7), 당일 확인(체크·확인자)
- **회고 항목 탭**: 고객 ID, 예식일, 빠진 요청(요청사항 연결), 사유 한 줄, 기록자. 당일 체크의 "빠짐"에서 생성되고 D+1 회고에서 읽는다. (2026-10-23 FRD 단계에서 추가)
- **할 일 탭**: 알림·D-day 기반 자동 생성 할 일 + 준성이 직접 추가한 할 일, 완료 여부
- **계정 탭**: 이름, 권한(운영자/스태프), 스태프 전용 링크 토큰, 활성. 준성이 시트에서 관리
- **알림**: 문의 즉시, 24시간 미응대(급함), 답사 전날, 견적 후 3·7일, 계약 직후, D-90/60/30/14(미입금 급함)/7/3/1, 당일 아침, D+1/7/30, 매일 아침. 확인하면 읽음 처리.

## 5. 화면 목록

주 사용 기기: 혼합 — 데스크톱 화면(운영 보드, 고객 사이클), 모바일 화면(오늘, 예식 당일 체크), 공용(접근 확인, 상담 기록 추가). 상담 기록 추가는 모바일은 전체 화면, 데스크톱은 고객 사이클 위 우측 패널로 연다. (2026-10-23 디자인 단계에서 승인)

| # | 화면 | 보여주는 것 | 기기 |
|---|---|---|---|
| 1 | 접근 확인 | 운영자는 준성 구글 계정, 스태프는 전용 링크로 입장. 그 외에는 "접근 권한 없음" 안내 (FRD·TRD 단계에서 자체 로그인 대신 변경) | 데스크톱·모바일 |
| 2 | 운영 보드 | 알림함, 월간 캘린더, 오늘 할 일, 새 문의, 파이프라인 | 데스크톱 |
| 3 | 고객 사이클 | 고객 한 명의 단계 진행, 상담 기록과 사진, 요청사항, 입금, 다음 할 일 | 데스크톱 |
| 4 | 오늘 | 오늘 할 일과 이번 주 행사 | 모바일 |
| 5 | 상담 기록 추가 | 통화·답사 직후 내용과 사진 입력, Gemini 요청사항 후보 | 모바일 · 데스크톱(우측 패널) |
| 6 | 예식 당일 체크 | 파트별 요청사항 체크, 레퍼런스 사진 확인, 빠진 항목 사유 기록 | 모바일 |
| 7 | 고객 목록 | 전체 고객 표(검색·단계 필터, 실패 고객 포함) | 데스크톱 |
| 8 | 알림함 | 지난 알림 전체 목록(안 읽음/전체 필터), 읽음 처리 | 데스크톱 |

7·8번은 2026-10-23 FRD 시안 대조에서 추가했다 (사이드바 "고객", "알림함" 메뉴의 목적지).

**편집 원칙 (2026-10-23 FRD 결정)**: 관리 화면에서는 현장 작업만 쓴다 — 할 일 체크·추가, 입금 확인, 상담 기록·요청사항 작성, 당일 체크, 알림 읽음. 단계 변경, 계약 정보, 예식 상세, 실패 처리, 예식일 수정은 구글 시트에서 직접 고치고, 화면은 시트 값을 다시 읽어 보여준다. 예외: "첫 연락 완료" 버튼은 화면에서 단계를 '연락'으로 바꾸고 24시간 미응대 알림을 끈다.

## 6. 범위 밖

- 고객용 챗봇, 카카오 알림톡, 고객용 홈페이지 디자인
- 화면 내 사진 업로드와 Gemini 요청사항 후보 추출은 2차 구현 (시안에는 포함)

## 7. 미정 항목 (시안에서 가정으로 처리)

- 관리 화면을 홈페이지 안 관리자 페이지로 둘지 별도 링크로 둘지 → [가정] 별도 링크
- 로그인 계정과 권한 → [가정] 준성 + 당일 스태프
- 로그인 방식 → **확정(2026-10-23 FRD·TRD)**: 운영자는 구글 계정 제한(준성만), 스태프는 시트 '계정' 탭에서 발급하는 전용 링크. 자체 아이디·비밀번호 로그인은 만들지 않는다
