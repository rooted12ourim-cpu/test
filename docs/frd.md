# 루티드 관리 화면 기능정의서 (FRD)

상태: 완료 (2026-10-23 확정 — 추정 4개 항목 포함 그대로 승인)

## ⓪ 범위 요약

- **필수 하위 기능: 60개** (F1 3 · F2 6 · F3 7 · F4 3 · F5 9 · F6 6 · F7 5 · F8 4 · F9 7 · F10 3 · F11 7)
- **예상 개발 작업 규모(대략)**: 중~대. 화면 7개 + 접근 불가 안내 1장 + 자동화 스크립트. 실제 작업은 세팅·시트 연결·마무리 점검이 더해져 합계보다 늘어난다. F11 자동화가 6시간 MVP에서 이미 만들어졌다면 그만큼 줄어든다.
- **복잡도를 높이는 요인**
  - 시트 여러 탭(메인·상담 기록·요청사항·회고·할 일·알림·계정)을 동시에 읽고 쓰는 구조
  - D-day 일정 재계산과 구글 캘린더 동기화
  - 알림 생성·해제 규칙(24시간 미응대의 예식 당일 보류, 입금 확인 시 해제)
  - 예약 가능 판단에 계약 + 검토 중 고객까지 대조
- **줄인다면 이 순서로**
  1. 할 일 직접 추가·삭제(F3.3·F3.4) → 부가 (−2): 자동 생성 할 일만 보인다
  2. 빠짐 사유 → 회고 자동 이동(F9.7) → 부가 (−1): "빠짐" 표시만 남고 회고는 시트에 직접 적는다
  3. 고객 목록 화면(F4.1·F4.2) → 부가 (−2): 고객은 운영 보드 검색으로만 찾고, 실패 고객을 모아 볼 곳이 없다

## ① 요약

웨딩 공간 루티드의 운영자(준성)가 문의부터 후기까지 고객 한 쌍의 여정을 보고, 현장 작업(할 일·입금 확인·상담 기록·요청사항·당일 체크·알림 읽음)만 화면에서 처리하는 Apps Script 웹앱. 그 외 정보 수정은 구글 시트에서 하고 화면은 다시 읽어 보여준다. 운영자는 준성 구글 계정으로, 스태프는 시트 '계정' 탭에서 발급하는 전용 링크로 접속하며, 스태프는 당일 체크 화면만 연다. 화면 뒤에서는 자동화 스크립트(F11)가 문의 브리핑, D-day 일정, 알림, 할 일을 만든다.

화면: 운영 보드 · 고객 목록 · 고객 사이클 · 알림함 (데스크톱) / 오늘 · 예식 당일 체크 (모바일) / 상담 기록 추가 (모바일 전체 화면 · 데스크톱 우측 패널) / 접근 권한 없음 안내

## ③ 핵심 기능 대표 시나리오

### 시나리오 1 — 새 문의부터 첫 연락 완료까지 (F11.1 → F3.7 → F10)

- **시작 조건**: 홈페이지 폼으로 문의가 들어와 문의원본 탭에 새 행이 생기고, 5분 안에 스크립트가 고객 탭으로 옮긴다 (예: 김하은, 웨딩, 2027-04-18 토 낮, 90명, 인스타그램).
- **정상 흐름**
  1. 스크립트가 새 행을 감지하고, 희망 날짜 1·2순위를 계약 고객·검토 중 고객과 대조해 예약 가능 여부를 정한다.
  2. 이름·연락처를 뺀 문의 내용을 Gemini에 보내 브리핑(요약, 통화 포인트, 첫 연락 문자 초안)을 받는다.
  3. 브리핑을 시트에 저장하고, 이름·연락처를 다시 붙여 #새-문의로 보낸다. 알림 탭에도 기록한다.
  4. 준성이 운영 보드 '새 문의'에서 김하은을 눌러 고객 사이클로 들어간다.
  5. 브리핑을 확인하고 "문자 초안 복사"로 초안을 복사해 직접 문자를 보낸다.
  6. "첫 연락 완료"를 누른다.
- **대표 예외**
  - Gemini 응답 실패: 브리핑 없이 고객 요약과 예약 가능 여부만 #새-문의로 보내고, 고객 사이클에 "브리핑 생성 실패" 표시를 남긴다. 문의 접수는 막지 않는다.
  - 24시간이 지나도 첫 연락 완료가 없으면 급함 알림을 만든다. 단, 그날 예식이 있으면 다음 날 아침 요약으로 미룬다.
- **완료 기준**: 단계가 '연락'이고, 첫 연락일이 오늘 날짜이며, 이 고객의 24시간 미응대 알림이 생기지 않았거나 해제된 상태.
- **데이터 변화**: 메인 시트 행 생성 → 브리핑·예약 가능 여부 칸 채움 → 알림 탭에 '문의 즉시' 1건 → (완료 시) 첫 연락일·진행 단계 갱신, 미응대 알림 해제
- **사용자가 보는 결과**: 디스코드 #새-문의에 브리핑이 도착한다. 운영 보드 새 문의 카드에 "예약 가능 / 검토 중 1팀 / 이미 계약 있음" 중 하나가 보인다. 첫 연락 완료 후에는 카드가 파이프라인 '연락' 열로 옮겨지고 빨간 표시가 사라진다.

### 시나리오 2 — 예식 당일 체크 (F9)

- **시작 조건**: 오늘 예식(박서준·이지민, 낮, 82명)이 있고, 요청사항 탭에 이 고객의 요청 18건이 있다. 운영자 또는 스태프 계정으로 접속한다.
- **정상 흐름**
  1. 당일 체크 화면이 오늘 예식으로 열리고, 진행률 "0 / 18"과 타임테이블이 보인다.
  2. 파트 필터 "플라워"를 눌러 3건만 본다.
  3. 아치 앞에서 사진 썸네일을 눌러 레퍼런스를 확인하고 체크한다. 카드에 "수진 11:42"가 기록된다.
  4. 모든 파트를 확인해 진행률이 "17 / 18"이 된다.
  5. 확인하지 못한 1건에 "빠짐"을 누르고 사유("비건 플레이트 2개만 준비됨")를 적는다.
- **대표 예외**
  - 잘못 체크한 경우: 다시 누르면 해제되고 확인자·시각이 지워진다.
  - 두 사람이 같은 항목을 거의 동시에 체크하면 나중에 저장된 확인자로 남는다.
  - 네트워크가 끊긴 경우: 체크가 저장되지 않았다는 표시를 보여주고 다시 시도하게 한다.
- **완료 기준**: 18건 모두 '확인' 또는 '빠짐' 상태.
- **데이터 변화**: 요청사항 탭의 당일 확인(체크 여부·확인자·시각) 갱신. 빠짐 1건마다 회고 항목 탭에 1행 생성.
- **사용자가 보는 결과**: 진행률 바가 차오르고, 확인한 카드는 흐려지며 취소선이 그어진다. 다음 날 D+1 회고 알림에 빠진 항목 1건이 함께 보인다.

- 예식 당일 미응대 알림을 다음 날 아침으로 미루는 보류 규칙

## ⑦ 표준 적용 항목 (구체 방식은 TRD에서)

- **접속 확인은 서버에서**: 화면 코드가 아니라 Apps Script 서버 쪽에서 계정을 확인한다 — 화면 코드를 고쳐서 우회할 수 없게.
- **권한 확인도 서버에서**: 스태프 계정이 다른 화면 주소를 직접 열어도 서버가 데이터를 주지 않는다 — 메뉴를 숨기는 것만으로는 막을 수 없어서.
- **연락처 기본 가림**: 화면에는 뒷자리 4개만 보이고 "연락처 보기"를 눌러야 전체가 보인다 — 화면을 옆에서 보거나 캡처할 때 노출을 줄이려고.
- **AI에 개인정보 미전송**: Gemini에는 문의 내용만 보내고 이름·연락처는 스크립트가 나중에 붙인다 — 외부 서비스에 고객 정보가 남지 않게.
- **API 키·웹후크 주소는 코드에 직접 쓰지 않음**: 스크립트 속성(비밀 설정 저장소)에 둔다 — 코드를 공유해도 키가 새지 않게.
- **같은 일을 두 번 하지 않기**: 같은 문의에 브리핑을 두 번 만들거나, 같은 D-day 알림을 두 번 보내지 않도록 처리 여부를 기록한다 — 스크립트가 다시 실행돼도 중복이 생기지 않게.
- **시간대 고정**: 모든 날짜·D-day 계산은 한국 시간(Asia/Seoul) 기준 — 서버 시간대 차이로 하루씩 밀리지 않게.
- **실패 기록**: 자동화가 실패하면 시트 '오류 기록'에 남기고 #오늘-할-일 아침 요약에 포함한다 — 조용히 실패해 알림이 빠지는 일이 없게.

## ⑧ 공통 동작 규칙

- **입력 검증**: 필수 칸(상담 기록: 고객·일시·방식·요약 / 요청사항: 파트·내용 / 빠짐: 사유)이 비면 저장 버튼을 누를 때 해당 칸 아래에 빨간 글씨로 알린다. 요청 내용은 한 줄(80자) 이내로 쓴다.
- **저장 결과 표시**: 저장에 성공하면 아래쪽에 "저장했습니다" 토스트를 띄운다. 실패하면 입력한 내용은 그대로 두고 "저장하지 못했습니다. 다시 시도" 버튼을 보여준다.
- **즉시 반영**: 체크·읽음·입금 확인은 누르는 즉시 화면에 반영하고 뒤에서 저장한다. 저장에 실패하면 원래 상태로 되돌리고 알린다.
- **시트 수정 반영**: 시트에서 고친 내용은 화면을 새로 열거나 새로고침하면 반영된다.
- **되돌리기 확인**: 요청사항 삭제, 입금 확인 되돌리기는 확인 창을 한 번 띄운다. 체크 해제는 확인 없이 바로 처리한다.
- **권한**: 스태프 계정에는 사이드바와 하단 탭 없이 당일 체크만 보인다. 등록되지 않은 계정에는 "접근 권한 없음 — 준성에게 계정 등록을 요청하세요"만 보인다.
- **빈 상태**: 데이터가 없는 목록에는 짧은 명사형 안내를 보여준다 (예: "새 문의 없음", "오늘 예식 없음").
- **문구**: 짧은 명사형, 느낌표·이모지 없음, 날짜는 "11월 7일(토)" 형식.

## ⑨ 인수 기준

- 준성이 아닌 구글 계정으로 운영자 링크를 열면 구글이 접근을 막고, 토큰이 틀리거나 비활성인 스태프 링크는 "접근 권한 없음"만 보여 고객 정보가 하나도 보이지 않는다.
- 스태프 링크로 열면 당일 체크 화면만 보이고, 다른 화면 기능을 직접 호출해도 고객 정보가 나오지 않는다.
- 홈페이지 폼으로 가짜 문의를 넣으면 5분 안에 #새-문의에 브리핑이 오고, 운영 보드 '새 문의'에 예약 가능 여부와 함께 보인다.
- 이미 계약된 날짜·슬롯으로 문의를 넣으면 "이미 계약 있음"이 표시된다. 같은 날짜·슬롯에 견적 단계 고객이 있으면 "검토 중 1팀"이 표시된다.
- 브리핑을 디스코드에서 열어 봐도 Gemini로 보낸 기록에 고객 이름과 연락처가 들어 있지 않다.
- 문의 후 24시간이 지나도록 첫 연락 완료를 누르지 않으면 빨간 "급함" 알림이 생긴다. "첫 연락 완료"를 누르면 그 알림이 사라지고 고객이 '연락' 열로 옮겨진다.
- 예식이 있는 날에는 24시간 미응대 알림이 디스코드 멘션으로 오지 않고, 다음 날 아침 요약에 들어간다.
- 시트에서 예식일을 바꾸면 구글 캘린더의 이전 D-day 일정이 사라지고 새 날짜 기준 일정이 생긴다. 같은 D-day가 두 개 보이지 않는다.
- 고객 사이클에서 잔금 "입금 확인"을 누르면 D-14 급함 표시가 사라지고, 되돌리면 다시 나타난다.
- 휴대폰에서 상담 기록을 쓰다 화면을 껐다 켜도 쓰던 내용이 남아 있다. 저장하면 고객 사이클 상담 기록 맨 위에 보인다.
- 상담 기록 추가 화면에서 요청사항을 직접 넣으면 그 예식의 당일 체크 화면에 같은 문장이 파트별로 보인다.
- 당일 체크에서 항목을 체크하면 확인자 이름과 시각이 카드에 찍히고 진행률 숫자가 1 오른다.
- "빠짐"에 사유를 적으면 회고 항목 탭에 한 줄이 생긴다.
- 운영 보드의 할 일을 체크하면 휴대폰 '오늘' 화면에서도 체크된 상태로 보인다.
