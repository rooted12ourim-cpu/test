# 루티드 관리 화면 디자인 프롬프트

상태: 완료

## 결정 기록

- **참고자료**: 기획서 톤 + AI 추천 (R1-C)
- **주 사용 기기**: 기획서대로 혼합 (R1-A)
- **무드**: 웜 페이퍼 (R2-A)
- **시안 제작 방법**: 외부 디자인 도구(Claude Design 또는 Google Stitch)에 화면별 블록을 붙여넣어 제작 (R2-B)
- **시안 결과물**: 이미지(PNG) 8장 + 디자인 토큰 문서 `design/DESIGN.md` (외부 디자인 도구 출력, 2026-10-23 저장)
- **고객 사이클 시안**: 05 대시보드형 채택. 08 타임라인형은 미채택(참고용으로만 보관)
- **상담 기록 추가 데스크톱 패널(07)**: 포함. 고객 사이클의 "+ 기록 추가"에서 우측 패널로 열림 (PRD 반영)
- **디자인 기준 승인**: 시안 + 이 문서의 '구현용 디자인 시스템'과 '불일치 구현 기준'을 구현 기준으로 확정 (2026-10-23)

## 공통 스타일 가이드

- **무드**: 웜 페이퍼. 노션처럼 조용한 문서형 업무 도구. 장식 없이 종이 위에 정리된 메모 느낌이다.
- **색 원칙**: 색은 "준성이 직접 손댈 곳"(파랑)과 "급한 알람"(빨강)에만 쓴다. 나머지는 아이보리·베이지·차콜 단계로 구분한다.
  - 바탕: 아이보리 `#FAF8F3` / 카드: 화이트 `#FFFFFF` / 테두리: 베이지 `#E7E2D6`
  - 본문 글자: 차콜 `#2B2A26` / 보조 글자: 웜그레이 `#7A766C`
  - 주 색상: 차분한 파랑 `#2F6FDB` (선택 상태, 주요 버튼, "내가 할 일" 테두리)
  - 보조 색상: 연한 베이지 `#F1EDE4` (단계 칩, 표 머리, 비활성 박스)
  - 급함: 빨강 `#D64545` (24시간 미응대, D-14 미입금 두 가지에만 쓴다)
  - 완료: 색 대신 차콜 체크 아이콘과 취소선을 쓴다
- **글자**: 각진 고딕 Pretendard. 제목 600, 본문 400. 데스크톱 본문 14px, 모바일 본문 16px. 숫자(금액·D-day)는 고정폭 숫자.
- **모서리·그림자**: 모서리 8px, 그림자 없음. 1px 베이지 테두리로만 구분한다.
- **반복 요소**
  - 단계 칩: 문의 / 연락 / 답사 / 견적 / 계약 / 완료 / 실패. 베이지 바탕의 작은 칩으로, 실패만 회색 점선 테두리를 쓴다.
  - D-day 배지: `D-14`처럼 고정폭 숫자. 7일 이내는 차콜 굵게, 급함 조건이면 빨강.
  - 알림 행: 시점 · 고객 이름 · 내용 한 줄 · 디스코드 채널 태그(#새-문의 / #오늘-할-일 / #예식-알람). 읽지 않은 알림은 왼쪽에 파란 점을 둔다.
  - 파트 태그: 주방 / 무대 / 플라워 / 음향 / 서빙
- **기기**: 데스크톱 화면은 1440px 폭, 좌측 사이드바(운영 보드 / 고객 / 알림함)를 둔다. 모바일 화면은 390px 폭, 하단 탭(오늘 / 기록 / 당일 체크)과 44px 이상 터치 영역을 쓴다.
- **문구 톤**: 짧은 명사형 ("잔금 확인", "답사 전날"). 느낌표와 이모지는 쓰지 않는다.

## 화면별 프롬프트 블록

블록을 하나씩 디자인 도구에 붙여넣으세요. 각 블록은 따로 붙여넣어도 되도록 공통 스타일을 매번 반복해 적었습니다. 고객 이름과 데이터는 모두 가짜 예시입니다.

### 1. 로그인

```
[화면] 루티드 관리 화면 – 로그인 (데스크톱 1440px와 모바일 390px 두 버전)
[공통 스타일] 웜 페이퍼 무드: 아이보리 바탕 #FAF8F3, 흰 카드, 1px 베이지 테두리 #E7E2D6, 차콜 글자 #2B2A26, 강조색은 차분한 파랑 #2F6FDB 하나, 급함만 빨강 #D64545. 글꼴 Pretendard, 모서리 8px, 그림자 없음. 장식 없는 노션풍 업무 도구.
[목적] 고객 이름·연락처·입금 정보를 보호하기 위해 운영자와 당일 스태프만 들어오게 한다.
[요소]
- 화면 가운데 400px 폭 흰 카드. 상단에 작은 워드마크 "rooted"와 그 아래 "관리 화면" 보조 글씨
- 아이디 입력, 비밀번호 입력(보기 토글 아이콘)
- "로그인 상태 유지 (12시간)" 체크박스
- 파란색 꽉 찬 "로그인" 버튼
- 오류 상태 예시: 비밀번호 칸 아래 빨간 글씨 "비밀번호가 맞지 않습니다 (남은 시도 2회)"
- 잠금 상태 예시: 카드 안 베이지 안내 박스 "5회 연속 틀려 10분간 잠겼습니다. 14:32 이후 다시 시도하세요"
- 카드 아래 작은 회색 글씨 "계정 문의는 준성에게"
[동작]
- 로그인 → 운영자 계정은 운영 보드, 스태프 계정은 예식 당일 체크 화면으로 이동
- 모바일에서는 카드가 화면 폭 전체(좌우 16px 여백)를 차지하고 입력칸 높이 48px
```

### 2. 운영 보드

```
[화면] 루티드 관리 화면 – 운영 보드 (데스크톱 1440px)
[공통 스타일] 웜 페이퍼 무드: 아이보리 바탕 #FAF8F3, 흰 카드, 1px 베이지 테두리 #E7E2D6, 차콜 글자 #2B2A26, 강조색은 차분한 파랑 #2F6FDB 하나, 급함만 빨강 #D64545. 글꼴 Pretendard, 모서리 8px, 그림자 없음. 장식 없는 노션풍 업무 도구.
[목적] 웨딩 공간 운영자가 아침에 열어 오늘 할 일, 새 문의, 급한 알람을 한 화면에서 확인한다.
[요소]
- 좌측 220px 사이드바: rooted 워드마크, 메뉴(운영 보드 / 고객 / 알림함 – 안 읽은 수 배지 "5"), 하단에 로그인 계정 "준성"
- 상단 바: 날짜 "10월 23일 목요일", 고객 검색창
- 1행 왼쪽 큰 카드 "알림함": 알림 행 6개. 각 행 = 왼쪽 파란 점(안 읽음) · 시점 · 고객 이름 · 내용 · 채널 태그. 맨 위 두 행은 빨간 배지 "급함":
  · "문의 후 26시간 · 김하은 · 아직 연락하지 않았습니다 · #새-문의"
  · "D-14 · 박서준·이지민 · 잔금 미입금 1,240만 원 · #예식-알람"
  · 나머지 예: "답사 전날 · 최유나 · 내일 14시 답사", "D-7 · 정민호·한소희 · 정육·수산 발주 (82명)", "견적 후 3일 · 오세린 · 팔로업", "계약 직후 · 윤재원 · D-day 일정 11개 생성 완료"
  · 각 행 오른쪽 "읽음" 텍스트 버튼, 카드 상단 "모두 읽음"
- 1행 오른쪽 카드 "오늘 할 일": 체크박스 목록 5개 (예: "김하은 첫 연락", "최유나 답사 준비", "정민호·한소희 인력 확정")
- 2행 왼쪽 카드 "월간 캘린더" 10월: 예식일은 파란 칸에 "낮 · 박서준" 식 라벨, 답사는 베이지 점, 오늘 날짜는 차콜 테두리
- 2행 오른쪽 카드 "새 문의" 3건: 이름 · 행사 종류 · 희망 날짜 · 인원 · 유입 경로 · 날짜 예약 가능 여부(가능 / 이미 계약 있음)
- 3행 전체 폭 "파이프라인": 문의(4) · 연락(3) · 답사(2) · 견적(3) · 계약(6) 다섯 열의 칸반. 각 카드에 고객 이름, 희망 날짜, 마지막 연락 후 경과일. 하단에 접힌 "실패 2건" 링크
[동작]
- 알림 행 클릭 → 해당 고객 사이클 화면으로 이동하고 읽음 처리
- 캘린더 예식 칸, 새 문의, 파이프라인 카드 클릭 → 고객 사이클 화면
- 오늘 할 일 체크 → 취소선과 차콜 체크로 바뀜
```

### 3. 고객 사이클

```
[화면] 루티드 관리 화면 – 고객 사이클 (데스크톱 1440px)
[공통 스타일] 웜 페이퍼 무드: 아이보리 바탕 #FAF8F3, 흰 카드, 1px 베이지 테두리 #E7E2D6, 차콜 글자 #2B2A26, 강조색은 차분한 파랑 #2F6FDB 하나, 급함만 빨강 #D64545. 글꼴 Pretendard, 모서리 8px, 그림자 없음. 장식 없는 노션풍 업무 도구.
[목적] 고객 한 쌍의 문의부터 후기까지를 한 줄로 보고, 지금 해야 할 다음 일을 바로 안다.
[요소]
- 좌측 220px 사이드바(운영 보드 / 고객 / 알림함), 상단에 "← 고객 목록"
- 헤더: "박서준 · 이지민" 큰 제목, 웨딩 · 2026년 11월 7일(토) 낮 · 82명, 단계 칩 "계약", D-day 배지 "D-14"(빨강, 잔금 미입금), 연락처는 클릭해야 보이는 "연락처 보기"
- 여정 바: 10칸 가로 스텝. 위 줄 문의 → 첫 연락 → 답사 → 견적 → 계약, 아래 줄 D-day 준비 → 예식 당일 → 정산·회고 → 후기 요청 → 콘텐츠화. 지난 칸은 차콜 체크, 현재 칸 "D-day 준비"는 파란 테두리, 앞으로 칸은 베이지. 각 칸 아래 작은 날짜
- "다음 할 일" 강조 카드(파란 테두리): "잔금 1,240만 원 입금 확인 · 최종 인원 확정 (D-14 · 10월 24일)"
- 본문 2열
  · 왼쪽 넓은 열 "상담 기록" 타임라인: 날짜 · 방식 칩(전화/답사/미팅/카톡) · 요약 3줄 · 레퍼런스 사진 썸네일 3장과 "+5"
  · 왼쪽 아래 "요청사항" 표: 파트 태그 · 요청 한 줄(예: "아치 비대칭, 그린·화이트 (사진 2장)") · 출처 · 고객 최종 확인(D-7) 체크 · 당일 확인
  · 오른쪽 좁은 열 "입금": 계약금 / 중도금 / 잔금 세 줄, 금액과 상태(입금 완료 = 차콜 체크, 미입금 = 빨간 글씨), 총액
  · 오른쪽 "D-day 일정": D-90 ~ D+30 세로 목록, 지난 일정은 취소선, 다음 일정은 파란 점
  · 오른쪽 "예식 상세": 최종 인원, 알레르기, 축가, 신부대기실 시간 등 키-값 목록
[동작]
- 상담 기록 "+ 기록 추가" → 상담 기록 입력 패널
- 사진 썸네일 클릭 → 드라이브 고객 폴더 미리보기
- 입금 줄 클릭 → 입금 여부 토글
- 예식일 수정 시 확인 창 "D-day 일정 11개가 다시 계산되고 기존 일정은 지워집니다"
```

### 5. 상담 기록 추가 (모바일)

```
[화면] 루티드 관리 화면 – 상담 기록 추가 (모바일 390px)
```

### 간격·모서리·그림자

- 간격 단위: 4 / 8 / 12 / 16 / 24px. 모바일 좌우 여백 16px, 카드 사이 12~16px, 카드 안쪽 16px

- 그림자: 없음. 층 구분은 바탕색 차이 + 1px `--border`만 사용
- 터치 영역: 최소 44px, 버튼·입력창 높이 48px, 모바일 체크 행 56px

### 반복 컴포넌트

- **버튼**: 주(파랑 채움·흰 글씨) / 보조(흰 바탕·베이지 테두리) / 텍스트(회색 글씨)
- **단계 칩**: `--surface-sub` 바탕, `--text-sub` 글씨, 4px. 실패는 점선 테두리
- **급함 배지**: `--urgent` 채움, 흰 글씨, 4px
- **D-day 칩**: 기본은 차콜 글씨, 급함 조건이면 `--urgent` 글씨 + `--urgent-bg`
- **여정 바**: 10칸. 완료 칸은 베이지 바탕 + 체크, 현재 칸은 `--primary` 채움 + NOW 라벨, 예정 칸은 베이지 바탕 + 흐린 글씨
- **알림 행**: 안 읽음 파란 점 · (급함 배지) · 시점 · 고객 이름(굵게) · 내용 · 채널 태그(`--surface-sub`) · "읽음"
- **체크 행**: 20px 체크박스(흰 바탕·베이지 테두리), 완료 시 차콜 체크 + 취소선 + 흐린 글씨, 오른쪽에 고객 이름 칩
- **파트 태그**: 주방 / 무대 / 플라워 / 음향 / 서빙. `--surface-sub` 바탕 4px
- **AI 후보 박스**: `--surface-sub` 바탕, 오른쪽 위 "Gemini 초안" 라벨, 채택된 후보는 파란 버튼 "채택됨"
- **사이드바(데스크톱)**: 폭 약 230px, 선택 메뉴는 흰 카드, 알림함 옆 빨간 숫자 배지, 하단 계정
- **하단 탭(모바일)**: 3개, 선택 탭은 `--primary` 아이콘·글씨
